# handwrite-scanner 설계 스펙

날짜: 2026-08-22

## 개요

프린트된 문서 양식에 수기(주로 한글)로 작성된 최종본 문서의 **사진**을 받아,
인식된 텍스트로 **PDF**를 만들어주는 **localhost 웹앱**.

## 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 인식 엔진 | 로컬 오픈소스만 (외부 API 금지, 데이터가 PC 밖으로 안 나감) |
| 실행 환경 | 저사양 사무용 PC/노트북, CPU 단독, localhost 웹앱 |
| 처리 시간 | 제한 없음 (밤새 배치 허용) |
| 양식 | 임의 양식 기본 동작 + 선택적 템플릿 등록(등록 시 인식률 향상, UI에서 등록 유도) |
| 출력 PDF | ⓐ 원본 이미지 + 투명 텍스트층(searchable) ⓑ 텍스트 재구성 PDF — 둘 다 |
| 인식률 전략 | 필드별 후보 목록 제약 + 유사도 대조 + 검수 UI |
| git 계정 | 이 레포는 Bun3 전용 |

## 엔진 선택

**Qwen2.5-VL-7B-Instruct, Q4 양자화 GGUF, llama-cpp-python으로 CPU 구동.**

- 한글 수기 인식에서 전통 OCR 오픈소스(EasyOCR/TrOCR류)보다 월등. Apache-2.0.
- 후보 제약을 프롬프트로 자연스럽게 전달 가능.
- RAM 요구 약 6~8GB → **RAM 16GB 권장**. 8GB PC용으로 3B 모델 설정 제공(config에서 모델 경로만 교체).
- AVX2 지원 CPU 필수(최근 10년 내 일반 CPU 전부 해당).
- 속도: 사무용 CPU 기준 필드당 수십 초, 문서 1장당 수 분~십수 분. 배치 전제라 허용.

검토 후 기각한 대안: 전통 OCR 파이프라인(한글 수기 정확도 부족, 글루 코드 과다),
kitae0522/hangul-recognition(음절 단일 분류기 + 폰트 합성 학습 데이터 → 실수기 부적합.
단, 손글씨 폰트 합성 데이터 기법은 향후 미세조정 시 참고 가치).

## 아키텍처

단일 Python **FastAPI** 앱: 정적 프론트(HTML+JS, 빌드 도구 없음) 서빙 + REST API +
백그라운드 인식 워커(스레드 1개, 순차 처리 — CPU라 병렬 무의미).

저장은 DB 없이 파일 시스템:

```
data/
  templates/<이름>/
    template.json        # 필드 좌표·라벨·타입·후보목록
    reference.<ext>      # 기준 이미지
  jobs/<id>/
    input/               # 업로드 원본 사진들
    status.json          # 대기/진행/완료/실패 + 진행률
    results.json         # 페이지·필드별 인식 결과(텍스트, 신뢰도, crop 좌표)
    output/              # 생성된 PDF
```

## 데이터 흐름

1. **업로드**: 사진 여러 장 + 템플릿 선택(선택사항) → job 생성, 큐 등록
2. **전처리**(OpenCV): 기울기 보정. 템플릿 있으면 기준 이미지와 ORB 특징점 정합 +
   homography로 사진을 템플릿 좌표계에 정렬
3. **인식**:
   - 템플릿 있음 → 필드 영역별 crop → VLM에 필드 단위 프롬프트
     ("이 필드는 '이름'이고 후보는 [...] 중 하나. 손글씨를 읽어 값만 답하라")
   - 템플릿 없음 → 페이지 전체를 "라벨: 값" JSON 구조화 추출.
     결과 화면에 "템플릿 등록 시 인식률 향상" 안내 배너
4. **후처리 검증**(LLM 환각 방어선):
   - 후보 목록 필드: 유사도 최근접 선택, 거리 기반 신뢰도 산출
   - 날짜/숫자/전화번호: 정규식 검증·정규화
   - 체크박스: 마킹 여부 판정
5. **검수 UI**: 필드 crop 이미지와 인식 텍스트를 나란히 표시, 저신뢰 필드 강조,
   클릭 수정. 수정값은 results.json에 반영
6. **PDF 생성**(reportlab):
   - ⓐ searchable: 원본 이미지 배경 + 각 필드 위치에 투명 텍스트(render mode 3)
   - ⓑ 재구성: "라벨: 값" 목록형 텍스트 PDF (레이아웃 복원은 하지 않음 — YAGNI)

## 템플릿 편집기 (웹, 1급 기능)

빈 양식(또는 샘플) 사진 업로드 → 브라우저에서 이미지 위에 드래그로 필드 박스 작성 →
필드마다 라벨 + 타입(자유텍스트/후보목록/날짜/숫자/체크박스) + 후보 목록(줄바꿈 구분
붙여넣기) 입력 → template.json 저장. 수정·삭제 가능.

## 화면 구성

1. 작업 목록/업로드 (진행률 표시, 완료 시 검수로 이동)
2. 템플릿 목록/편집기
3. 검수 화면 (필드별 확인·수정 → PDF 생성 버튼)
4. 다운로드 (PDF 2종)

## 에러 처리

- 정합 실패(다른 양식·심한 왜곡) → 템플릿 없는 전체 추출로 폴백 + 결과에 경고 표시
- 모델 로드 실패/메모리 부족 → 3B 모델 안내 메시지
- 서버 재시작 → status.json 기준으로 미완료 job 재개
- 업로드 검증: 이미지 파일 여부·크기 제한(트러스트 바운더리)

## 테스트

- 후처리 로직(유사도 매칭, 정규식 검증, 신뢰도 산출): 단위 테스트
- 파이프라인: 샘플 이미지 1장 스모크 테스트 (모델 자체 정확도는 테스트 대상 아님)

## 구현하지 않는 것 (YAGNI)

- 다중 사용자/인증 (localhost 단독 사용)
- DB (파일 시스템으로 충분)
- 재구성 PDF의 원본 레이아웃 복원
- 모델 미세조정 (인식률이 실사용에서 부족할 때 재검토)
- GPU 지원 (llama.cpp가 어차피 GPU 자동 활용 가능하나 별도 작업 안 함)
