# 설치 프로그램과 선택 문서 검사

사용자가 승인한 범위: 설치용 EXE, 여러 등록 양식 중 일치 문서만 검사, PDF 페이지 선택.

## 설계

- Inno Setup으로 사용자별 설치 EXE를 생성한다. 실행 바로가기와 제거 항목을 등록한다. 설치 폴더의 data/engine은 설치·제거 대상에서 제외한다. 기존 폴더를 설치 위치로 지정해 데이터를 유지할 수 있다. 자동 업데이트용 ZIP도 유지한다.
- app/intake.py: 임시 업로드와 PDF 페이지 수·저해상도 미리보기. 토큰으로 원본을 재사용하고 24시간 지난 임시 입력은 다음 업로드 때 정리한다. 시작 요청은 같은 토큰에 대해 중복 작업을 만들지 않는다.
- 작업 시작 시 양식 목록과 파일별 1부터 시작하는 페이지 목록을 검증·저장한다. 하나 이상 양식과 페이지가 필요하다. 미선택 페이지는 렌더링하지 않는다.
- 작업 내부 page는 연속 인덱스로 유지해 이어하기·필드 수정 호환성을 지킨다. source_file/source_page로 원본 위치를 표시하고 내보낸다.
- 새 다중 양식 작업은 ORB 최고 점수의 등록 양식만 채택하고 미일치는 skipped 결과로 기록한다. 판별 엔진이 없으면 명시적 오류. 이전 작업은 저장된 처리 방식으로 이어갈 수 있다.
- UI는 업로드 후 페이지 미리보기, 파일별 전체/해제와 범위 입력, 양식 체크박스를 제공한다. 선택 수와 접수/준비 상태를 표시한다.

## 구현·검증 순서

1. 실제 PDF 선택·원본 번호·재개, 다중 양식 미일치 건너뜀, 잘못된 요청 테스트를 먼저 실패시킨다.
2. 입력 보관/API, jobs 변환, worker 판별, 결과 표시를 구현해 테스트를 통과시킨다.
3. 실제 브라우저로 페이지/양식 선택 및 실패·재시도 흐름을 검증한다.
4. 설치 EXE를 빌드하고 격리 폴더에서 설치·재설치·실행·제거 시 사용자 데이터 보존을 검증한다.
5. 릴리스 소스 테스트와 실제 배포 파일 검증 후 설치 EXE와 업데이트 ZIP을 게시한다.
